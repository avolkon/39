# Архитектурная спецификация проекта (Технический дизайн)

**Проект:** ChemAI: Predict the Cure – ML-пайплайн для предсказания биологической активности химических соединений  
**Версия:** 1.0  
**Статус:** Утверждена

Документ описывает целевую архитектуру ML-решения для хакатона, включая пайплайн обработки данных, обучение моделей, предсказание и воспроизводимость. Синхронизирован с `ТЗ_Хакатона.txt` и предыдущими обсуждениями (учёт химических особенностей, независимое предсказание SI, использование `uv`, блок-схема и структура проекта).

---

## Согласованные архитектурные решения

| Пункт / обсуждение | Утверждённая реализация | Обоснование |
|-------------------|--------------------------|-------------|
| Связь SI с IC50/CC50 | **SI предсказывается независимо**, не вычисляется как CC50/IC50 | В предоставленных данных (sample_submission.csv) связь отсутствует; организаторы ввели SI как отдельный таргет |
| Логарифмическое преобразование | `log1p` для IC50 и CC50, для SI – по выбору (проверить распределение) | Концентрации варьируют на порядки; логарифмирование улучшает RMSE в исходном масштабе |
| Химический инжиниринг признаков | Добавить 5–10 дополнительных признаков (MolLogP/TPSA, ароматические кольца/HeavyAtom, зарядовые суммы и др.) | Улучшает обобщение на малой выборке (750 объектов) |
| Валидация | Кросс-валидация по кластерам (scaffold-like) на основе молекулярных дескрипторов | Случайная CV может быть оптимистичной из-за схожих структур в трейне/тесте |
| Модели | Ансамбль: LightGBM, XGBoost, Ridge, многозадачная нейросеть (опционально) | Разные модели компенсируют слабости друг друга; нейросеть с малой долей (0.2) |
| Оценка неопределённости | Опционально: dropout MC или квантильная регрессия для v2 | В хакатоне не требуется, но для реальной фармы критично |
| Инструменты | `uv` для зависимостей, `ruff` для линтинга, `pytest` для тестов | Современный быстрый менеджер пакетов, соответствие лучшим практикам |
| Структура проекта | `app/` – корневой пакет с подмодулями: `features/`, `models/`, `preprocessing/`, `validation/`, `utils/` | Чёткое разделение слоёв (аналогично FastAPI-проекту) |

## Общая архитектура

### 1. Контракты между компонентами

#### Контракт Data Loader → Preprocessing

```python
# Интерфейс загрузки данных
interface DataLoader:
    def load_train() -> pd.DataFrame  # 750 строк, 214 признаков + 3 таргета
    def load_test() -> pd.DataFrame   # 250 строк, 214 признаков
    def load_sample() -> pd.DataFrame # формат submission
```

**Обязательные правила:**
- Загрузчик не выполняет модификацию данных.
- Возвращает копию исходных данных.

#### Контракт Feature Engineering → Preprocessing / Models

```python
interface FeatureEngineer:
    def add_chem_features(df: pd.DataFrame) -> pd.DataFrame
    # Добавляемые признаки:
    # - LogP_TPSA = MolLogP / (TPSA + 1e-6)
    # - Arom_Heavy_ratio = RingCount (ароматические) / HeavyAtomCount
    # - Charge_sum = MaxPartialCharge + MinPartialCharge
    # - fr_imide_flag, fr_sulfone_flag (бинарные по наличию)
    # - ... до 10 признаков
```

**Обязательные правила:**
- Признаки вычисляются на основе исходных 214 дескрипторов.
- Не используют таргеты.
- Применяются одинаково к трейну и тесту.

#### Контракт Preprocessing → Model Training

```python
interface Preprocessor:
    def fit(df: pd.DataFrame) -> None   # вычисляет mean, std, удаляет низкодисперсные признаки
    def transform(df: pd.DataFrame) -> np.ndarray  # масштабирование, отбор
    def get_feature_names() -> list[str]
```

**Обязательные правила:**
- `fit` только на обучающей выборке.
- Удаление признаков с нулевой дисперсией или >30% пропусков.
- Стандартизация (`StandardScaler`).

#### Контракт Model → Predictions

```python
# Каждая модель реализует интерфейс
interface SingleTargetModel:
    def fit(X: np.ndarray, y: np.ndarray) -> None
    def predict(X: np.ndarray) -> np.ndarray

# Для IC50, CC50, SI – отдельные экземпляры
```

**Обязательные правила:**
- Модели не изменяют входные данные.
- Для IC50/CC50 обучение на `log1p(y)`, предсказание возвращает `expm1(pred)` внутри постобработки.

#### Контракт Ensemble → Submission

```python
interface Ensemble:
    def predict(X: np.ndarray) -> dict[str, np.ndarray]  # {'IC50': ..., 'CC50': ..., 'SI': ...}
```

**Обязательные правила:**
- Усреднение предсказаний (среднее арифметическое или взвешенное по валидационной RMSE).
- Постобработка: обрезка отрицательных значений (`IC50,CC50 < 0 → 1e-8`, `SI < 0 → 0`).

#### Контракт Validation → Model Selection

```python
interface Validator:
    def split(X, y, n_splits=5) -> list[tuple(train_idx, val_idx)]
    # реализация: кластеризация по признакам (например, MolLogP, RingCount, TPSA)
```

**Обязательные правила:**
- Не использовать случайное разбиение без стратификации.
- Стратификация по квантилям SI (или кластеры).

### 2. Диаграмма последовательности (основной сценарий – обучение)

```text
DataLoader   FeatureEngineer   Preprocessor   Validator   Model(4 типа)   Ensemble   Evaluator
    │              │               │             │             │             │           │
    │ load_train() │               │             │             │             │           │
    ├─────────────>│               │             │             │             │           │
    │              │ add_chem_features()         │             │             │           │
    │              ├──────────────>│             │             │             │           │
    │              │               │ fit()       │             │             │           │
    │              │               ├────────────>│             │             │           │
    │              │               │ transform() │             │             │           │
    │              │               ├────────────>│ (X_scaled)  │             │           │
    │              │               │             │ split()     │             │           │
    │              │               │             ├────────────>│ (фолды)     │           │
    │              │               │             │             │             │           │
    │              │               │             │ for each fold:            │           │
    │              │               │             │             │ fit/predict │           │
    │              │               │             │             ├────────────>│           │
    │              │               │             │             │ predictions │           │
    │              │               │             │             │<────────────┤           │
    │              │               │             │             │             │           │
    │              │               │             │             │ aggregate   │           │
    │              │               │             │             │─────────────>│           │
    │              │               │             │             │             │ calc RMSE │
    │              │               │             │             │             ├──────────>│
    │              │               │             │             │             │ metric    │
    │              │               │             │             │             │<──────────┤
    │              │               │             │             │             │           │
    │              │               │ после CV – обучить на всех данных        │           │
    │              │               │<────────────┤             │             │           │
    │              │<──────────────┤             │             │             │           │
    │<─────────────┤               │             │             │             │           │
    │ сохранить модели, scaler, feature list                             │           │
```

### 3. Схема данных

| Компонент | Хранилище | Данные | TTL / сохранение | Ключ / таблица |
|-----------|-----------|--------|------------------|----------------|
| Исходные данные | CSV-файлы | train.csv (750×217), test.csv (250×214) | бессрочно | `data/` |
| Промежуточные признаки | Numpy массивы (сохраняются опционально) | X_train_scaled, y_train_log1p | временно | память |
| Обученные модели | `.pkl` / `.joblib` файлы | LightGBM, XGBoost, Ridge, нейросеть (3 таргета × 4 модели = 12 файлов) | бессрочно | `models_saved/` |
| Трансформеры | `.pkl` файлы | scaler.pkl, feature_columns.pkl, selector.pkl | бессрочно | `models_saved/` |
| Предсказания | CSV-файл | final_submission.csv (250×4) | до следующего запуска | `submissions/` |

**Связи:**  
- `train.csv` → после инжиниринга признаков → `X_train` (матрица)  
- `test.csv` → те же трансформации → `X_test`  
- Предсказания сохраняются в формате `index,IC50,CC50,SI`.

### 4. Протоколы взаимодействия

| A → B | Протокол | Данные | Порт/URL (или файл) |
|-------|----------|--------|---------------------|
| Скрипт → CSV | файловый ввод/вывод | pandas read_csv/write_csv | `data/`, `submissions/` |
| Скрипт → модели | `pickle` / `joblib` | бинарные файлы | `models_saved/` |
| Обучение → память | numpy / pandas | массивы в RAM | – |
| (Опционально) Модель → GPU | CUDA | тензоры | – |
