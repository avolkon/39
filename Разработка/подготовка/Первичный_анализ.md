## 1. План ML-архитектора (по ТЗ хакатона)

### 1.1. Понимание задачи и данных
- **Цель:** предсказать три регрессионные переменные (`IC50`, `CC50`, `SI`) для 250 тестовых молекул по 214 числовым дескрипторам.
- **Обучающая выборка:** 750 объектов – достаточно для базовых моделей, но мало для глубокого обучения без регуляризации.
- **Особенности:** `SI` связан с `IC50` и `CC50` соотношением `SI = CC50 / IC50` (индекс селективности). В задании его нужно предсказывать как отдельную переменную, но эту связь можно использовать для повышения качества.

### 1.2. Исследовательский анализ данных (EDA)
- Проверить пропуски (если есть – заполнить медианой или удалить признаки с >30% пропусков).
- Проанализировать распределение таргетов: для концентраций (`IC50`, `CC50`) характерно логнормальное распределение – применить `log1p`-трансформацию. `SI` часто имеет скошенное распределение – возможно, тоже логарифмировать.
- Построить парные графики (`IC50` vs `CC50`, `SI` vs `CC50/IC50`). Выявить выбросы (например, если `CC50/IC50` сильно отличается от `SI` – возможны ошибки в данных).
- Оценить корреляцию признаков между собой и с таргетами. Удалить высококоррелированные (порог >0.95), низковариативные (дисперсия <0.01).

### 1.3. Предобработка признаков
- Масштабирование: `StandardScaler` или `RobustScaler` (устойчив к выбросам).
- Отбор признаков: использовать важность из `RandomForest` или `LightGBM`, отобрать топ-K (например, 100-150). Возможно, применить `SelectKBest` (на основе взаимной информации или F-регрессии).
- Дополнительные признаки: на основе химического смысла создать новые дескрипторы – например, `LogP / TPSA`, отношение количества доноров/акцепторов водородных связей (если есть соответствующие `fr_*`), `MolLogP * RingCount`.

### 1.4. Стратегия моделирования

**Вариант A: Три независимые модели** (просто, интерпретируемо)  
- Для каждого таргета обучить ансамбль: `LightGBM + XGBoost + CatBoost + Ridge` с блендингом или стекингом.
- Кросс-валидация: 5-кратная стратифицированная по квантилям `SI` (чтобы сохранить распределение).

**Вариант B: Многозадачная нейронная сеть** (может использовать общие представления)  
- Архитектура: несколько общих полносвязных слоев (e.g., 256→128→64) с Dropout/BatchNorm, затем три головы по 2-3 слоя для каждого таргета.
- Функция потерь: взвешенная сумма MSE (или MAE) для трёх выходов. Веса можно подобрать, чтобы сбалансировать шкалы.
- Дополнительно добавить вспомогательную потерю, которая штрафует отклонение `pred_SI` от `pred_CC50 / pred_IC50`.

**Рекомендация:** объединить оба подхода – обучить многозадачную сеть и ансамбль бустингов, затем усреднить предсказания (среднее или взвешенное по валидационной RMSE).

### 1.5. Учёт связи `SI = CC50 / IC50`
- Обучить модели на `IC50` и `CC50` отдельно, затем вычислить `SI_computed = CC50_pred / IC50_pred`. Сравнить с прямой моделью для `SI`. Взять взвешенное среднее между прямым предсказанием и вычисленным (например, 0.3*SI_direct + 0.7*SI_computed).
- Можно применить «калибровку»: обучить легкую модель (линейную) на предсказанных `(IC50, CC50)` для целевого `SI`.

### 1.6. Оптимизация и валидация
- Поиск гиперпараметров через `Optuna` с минимизацией средней RMSE на кросс-валидации.
- Для бустингов: количество деревьев, скорость обучения, максимальная глубина, регуляризация.
- Для нейросети: количество слоёв, dropout, learning rate.
- Контроль переобучения: ранняя остановка, аугментация данных (например, добавление шума в дескрипторы).

### 1.7. Постобработка
- Обратное преобразование из логарифмического масштаба (`expm1`).
- Проверка реалистичности: `IC50`, `CC50` должны быть положительными. Если модель выдала отрицательное значение – заменить на очень малое положительное (1e-6).
- Убедиться, что `SI >= 0`. Теоретически `SI > 1` означает высокую селективность.

### 1.8. Финальный пайплайн
1. Загрузить `train.csv`, `test.csv`.
2. Применить те же трансформации (масштабирование, отбор признаков), что обучены на трейне.
3. Сделать предсказания ансамблем.
4. Сохранить `sample_submission.csv` с колонками `index, IC50, CC50, SI`.

## 2. Критика и дополнения с точки зрения химика-нобелевского лауреата

*(Роль: профессор, автор синтеза более 500 биологически активных молекул, лауреат Нобелевской премии по химии за вклад в молекулярный дизайн)*

Уважаемый коллега, ваш ML-план технически грамотен, но, как химик, работающий на стыке синтеза и биологии, я вижу несколько принципиальных упущений. Позвольте высказаться по пунктам.

### 2.1. О грубой ошибке: отношение `SI = CC50 / IC50`
Вы пишете: «SI связан с IC50 и CC50». Но в реальной фармакологии **индекс селективности строго определяется как `SI = CC50 / IC50`** (причём обе концентрации в одних единицах, обычно мкМ). Это не просто корреляция – это определение.  
Если организаторы хакатона просят предсказывать SI отдельно, то, вероятно, они зашумляют данные или используют другую формулу? Но, посмотрев файл `sample_submission.csv`, я вижу, что для многих образцов `SI` **не равен** `CC50/IC50`. Например, строка 0: `IC50=0.7237, CC50=0.4263, SI=0.3085`, а `0.4263/0.7237 = 0.589`. Разница огромная. Значит, данные либо синтетические, либо `SI` пересчитан по другой формуле (возможно, `SI = 1 - (IC50/CC50)`? Давайте проверим: `1 - 0.7237/0.4263` отрицательный). Или они добавили шум.  
**Вывод:** в этом датасете **нельзя** полагаться на математическую связь. Организаторы намеренно сделали SI независимым таргетом, чтобы усложнить задачу. Ваш план использовать вычисление `CC50/IC50` для постобработки приведёт к катастрофе, потому что истинное соотношение в данных отсутствует.  
**Моё предложение:** полностью игнорировать аналитическую связь и обучать три полностью независимые модели. Или, если есть время, проверить корреляцию между `SI` и `CC50/IC50` на обучающей выборке – почти наверняка она будет очень низкой.

### 2.2. О природе дескрипторов и химической интерпретации
Вы предлагаете отбор признаков по корреляции и важности. Но многие из 214 дескрипторов (например, `BCUT2D_*`, `FpDensityMorgan*`) являются сжатыми отпечатками, которые коллинеарны по построению. Удаляя их, вы потеряете способность различать изомеры и региоизомеры.  
Я бы настоял на **сохранении всех признаков** и использовании регуляризованных моделей (Ridge, ElasticNet) в ансамбле с деревьями. Древесные модели автоматически обрабатывают коллинеарность, а линейные – нет. Но для нейросетей коллинеарность не страшна.

### 2.3. О логарифмическом преобразовании таргетов
IC50 и CC50 в реальных экспериментах варьируются на 6-8 порядков (от нМ до мМ). Ваше предложение логарифмировать – верное. Однако не забудьте, что после обратного преобразования среднеквадратичная ошибка в исходном масштабе будет сильно зависеть от больших значений. В метрике RMSE по исходным значениям большие ошибки на крупных концентрациях доминируют.  
**Альтернатива:** оптимизировать RMSE в логарифмическом пространстве, а затем преобразовывать обратно – это стандартный приём. Но убедитесь, что в тестовых данных нет выбросов, которые при обратном преобразовании дадут нереалистичные значения (например, 10^6 мМ – это чистый яд).

### 2.4. О недостатке химического инжиниринга признаков
Ваш план – чисто data-driven. Как химик-синтетик, я могу подсказать несколько дескрипторов, которые обычно дают высокую предсказательную силу для цитотоксичности и противовирусной активности:
- **Отношение `MolLogP` к `TPSA`** – характеризует проникновение через мембрану.
- **Количество ароматических колец, делённое на `HeavyAtomCount`** – влияет на интеркаляцию в ДНК/РНК.
- **Суммарный заряд в физиологических условиях (pH 7.4)** – можно оценить через pKa, но у вас нет pKa – тогда использовать `MinPartialCharge` и `MaxPartialCharge` как суррогаты.
- **Наличие специфических групп** (например, `fr_imide`, `fr_sulfone`) – известно, что они повышают селективность к вирусным протеазам.
Добавьте 5–10 таких признаков – они могут улучшить обобщение, особенно при малом объёме выборки.

### 2.5. О валидации с учётом химического разнообразия
Случайная 5-кратная кросс-валидация может дать слишком оптимистичную оценку, если в выборке есть кластеры похожих молекул. В химии часто применяют **кросс-валидацию по скэффолдам** (scaffold split) – разделение по базовому каркасу молекулы. В вашем датасете нет явных scaffold-признаков, но можно использовать кластеризацию дескрипторов (например, по `MolLogP`, `RingCount`, `NumAromaticRings`) и делать стратифицированные фолды по кластерам. Иначе модель запомнит локальные паттерны и не обобщится на новые химические типы.

### 2.6. О неопределённости предсказаний
В фармацевтической разработке критически важно знать, насколько можно доверять предсказанию. `RMSE` усреднённая – грубая метрика. Я бы добавил в ваше решение **оценку неопределённости** (например, квантильную регрессию или dropout в нейросети с Monte Carlo sampling). Тогда для каждого тестового соединения можно выдавать интервал, в котором с вероятностью 90% лежит истинное значение. Организаторы хакатона это не просят, но для реального применения – обязательно.

### 2.7. О малом объёме данных (750 строк)
Вы предлагаете ансамбль из трёх бустингов и нейросеть. При таком размере выборки глубокие сети могут переобучаться сильнее, чем бустинги. Я бы сделал основной упор на `LightGBM` с агрессивной регуляризацией (`lambda_l1`, `lambda_l2`, `min_child_samples`). Нейросеть использовать только как дополнительного участника ансамбля с малым весом (например, 0.2).

### 2.8. Финальный совет: простота важнее сложности
Выигрыш в 1–2% RMSE за счёт многоэтапного ансамбля часто нивелируется на тесте, если данные зашумлены. Поскольку это хакатон, я бы предложил:
- Обучить `LightGBM` отдельно для каждого таргета с логарифмической трансформацией.
- Сделать `Stacking` с `Ridge` в качестве мета-модели.
- Использовать 10-кратную кросс-валидацию вместо 5-кратной (стабильнее).
- И самое главное: **не пытайтесь вывести SI из IC50/CC50** – вы уже видели, что в предоставленном семпле эта связь не выполняется. Это ключевой момент, который разделяет успешное решение от провала.
