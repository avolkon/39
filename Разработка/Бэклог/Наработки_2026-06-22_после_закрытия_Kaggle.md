## 2. За счёт чего удалось улучшить результат до **345.08** (E3)

Лучший **репозиторный** public LB за серию 22.06 — **345.08** (`submission_baseline_epic10_step1.csv`). Это **на ~4.2 балла лучше** исторического `submission2_a4` (**349.31**) и **на ~18 баллов лучше** «голого» baseline репо (**363.07**, E2).

### 2.1. Факторы улучшения (по убыванию вклада)

| # | Изменение | Механизм | OOF / LB |
|---|-----------|----------|----------|
| 1 | **Отказ от stacking в `train.py`** (`CHEM_USE_STACKING=false`) | In-sample meta на OOF давал LB **1447**; baseline-ансамбль стабилен | E1 vs E2 |
| 2 | **Clipping OOF и предсказаний** (`clip_oof_matrix`, `pred_to_original`, `Expm1Predictor(max_log)`) | Убраны численные «хвосты» expm1 после log-трансформа IC50/CC50 | OOF 644→591 |
| 3 | **Tree-only ансамбль** (`CHEM_INCLUDE_LINEAR_MODELS=false`) | Ridge/Elastic/Bayesian нестабильны на жёстком CV; веса ~0, но шумят OOF | Доп. −3…−5 OOF |
| 4 | **ClusterKFold** (не меняли на этом шаге) | Сохранена стратегия, согласованная с лучшими `submission*_a4` | — |
| 5 | **`optimize_blend_weights`** по `competition_score` | Веса под общую метрику платформы, не per-target RMSE | Фаза 1 |

### 2.2. Что **не** дало выигрыша на LB

| Эксперимент | OOF | Public LB | Вывод |
|-------------|-----|-----------|-------|
| OOF stacking в репо (E1) | 878 | **1447** | Meta переобучена на OOF; не для продакшена |
| `duplicate_group` + CatBoost + SI (E4) | **531** | **355** | OOF ↓59, LB ↑10 — CV не калиброван к платформе |
| SI blend `w=1.0` | — | — | На train SI≈CC50/IC50; blend не помог |
| GroupKFold (истор.) | улучшался | **373** | Уже зафиксировано в презентации |

### 2.3. Рекомендуемый «рецепт 345» для будущего (не в текущем git)

## 6. Предложения для развития проекта (после хакатона)

### 6.1. Краткосрочно (если снова откроют LB или для портфолио)

1. **В cherry-pick только Epic 10** (`d37cd76`) поверх текущего `train.py` — clip + tree-only без смены CV.
2. **Не включать** `duplicate_group` как канон без подтверждения LB.
3. Восстановить **23 теста** Фазы 1 без merging всего stacking-пути.
4. Зафиксировать **submission_baseline_epic10_step1.csv** как эталон «лучший репо-LB».

### 6.2. Среднесрочно (методология)

1. **Multitask / shared trunk** — одна модель на три таргета с учётом SI≈CC50/IC50.
2. **Constrained inference** — SI = f(IC50, CC50) с learnable w только если платформа подтверждает.
3. **Seed ensemble** (5–10 seeds) + OOF stacking **с nested meta** (Фаза 1).
4. **Optuna** на LGB/XGB/CatBoost с целью `competition_score`, не per-target RMSE.
5. **Shift-aware weights** — downweight train-строк с экстремальным covariate shift (fr_oxazole, RingCount).

### 6.3. Долгосрочно (оригинальность + баллы)

1. Graph neural nets / molecular fingerprints (если разрешат SMILES).
2. Domain adaptation train→test.
3. Ablation-таблица в README для критерия «обоснование» (до 5 баллов).
4. CI: pytest + ruff + pip-audit (см. ИБ-ревью).
