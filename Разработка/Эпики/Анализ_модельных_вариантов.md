# Анализ модельных вариантов (не менее 9 типов на каждый таргет)

Требование: **для каждого из трёх таргетов** (`IC50`, `CC50`, `SI`) проанализировать и использовать **не менее девяти разнородных типов** моделей, наиболее подходящих для табличной регрессии при **~750 объектах** и **сотнях числовых дескрипторов**. Набор алгоритмов один и тот же по составу (9 базовых + опционально CatBoost), но **релевантность и ожидаемая роль** для концентраций и для SI различаются — ниже. Итоговый вклад каждого типа в предсказание **конкретного** таргета задаётся **эмпирически**: средняя RMSE по кластерной CV → веса в ансамбле (`metrics.json`).

## Сводная таблица: 9 базовых типов

| № | Модель | Класс идей | Плюсы на малых n | Риски / ограничения |
|---|--------|------------|------------------|---------------------|
| 1 | **LightGBM** | Gradient boosting (leaf-wise) | Сильный табличный baseline, л2/фракции признаков, ES | Чувствителен к настройке; при утечке в CV завышает метрику |
| 2 | **XGBoost** | Gradient boosting (level-wise) | Другой bias, хорош в ансамбле с LGB | Те же, что у бустингов |
| 3 | **Ridge (RidgeCV)** | Л2-регуляризация | Стабилен при мультиколлинеарности дескрипторов | Нелинейные зависимости хуже деревьев |
| 4 | **ElasticNetCV** | Л1+Л2, авто-альфа | Отбор/сжатие коэффициентов, иной компромисс | Нужна стандартизация (есть в Preprocessor) |
| 5 | **HistGradientBoosting** (sklearn) | Гистограммный бустинг | Быстрый нативный sklearn, мало гиперпараметров | Слабее тюнингуемый чем LGB/CB на сложных данных |
| 6 | **RandomForest** | Бэггинг глубоких деревьев | Устойчивость к шуму, **уменьшение дисперсии** | Смещение на очень шумных таргетах |
| 7 | **ExtraTrees** | Случайные пороги | Часто **меньше переобучения** при малой выборке | Может недообучать слабые сигналы |
| 8 | **GradientBoosting** (sklearn) | Классический бустинг | Ещё один независимый бустинг против LGB/XGB | Дольше, чем HGBR |
| 9 | **BayesianRidge** | Линейный с априором | Регуляризация «мягче» Ridge при шуме, быстрый | Всё ещё линейная модель |
| 10 | **CatBoost** (опция) | Ordered boosting | Доп. разнообразие бустинга, устойчивость к смещениям | Тяжёлая опциональная зависимость |

## Подбор под **IC50** (концентрация, обучение в `log1p`)

| Тип | Насколько уместен | Зачем именно для IC50 |
|-----|-------------------|------------------------|
| LightGBM / XGBoost / HistGBRT / GBR | **Высоко** | Нелинейные зависимости «структура → активность»; `log1p` стабилизирует дисперсию по порядкам концентраций. |
| RandomForest / ExtraTrees | **Высоко** | Сглаживание шума измерений IC50, робастность на малых n. |
| Ridge / ElasticNet | **Средне–высоко** | Дескрипторы RDKit часто коллинеарны; линейный слой ловит глобальные направления в лог-шкале. |
| BayesianRidge | **Средне–высоко** | Мягкая регуляризация, иной компромисс bias–variance рядом с Ridge. |
| CatBoost (опция) | **Высоко** | Ещё один сильный табличный бустинг; полезен в смеси с LGB/XGB. |

*Итого:* для IC50 все девять базовых семейств **уместны**; приоритет — **бустинги + леса** за нелинейность, **линейные трио** — за структуру признакового пространства.

## Подбор под **CC50** (цитотоксичность, тоже `log1p`)

| Тип | Насколько уместен | Зачем именно для CC50 |
|-----|-------------------|------------------------|
| LightGBM / XGBoost / HistGBRT / GBR | **Высоко** | CC50 часто связана с липофильностью, полярностью, размером — нелинейные пороги хорошо ловятся деревьями. |
| RandomForest / ExtraTrees | **Высоко** | Токсичность может быть зашумлена; бэггинг/рандомизация порогов снижает переобучение. |
| Ridge / ElasticNet / BayesianRidge | **Средне–высоко** | Общие физико-химические тренды (полярность, заряд) часто почти линейны в лог-шкале концентрации. |

*Итого:* состав **те же 9 типов**, что для IC50; отличие в **распределении весов** после CV (какой алгоритм стабильнее именно на CC50).

## Подбор под **SI** (отдельная переменная, **без** `log1p` по умолчанию)

По данным соревнования **SI не воспроизводится как CC50/IC50** (см. `Первичный_анализ.md`), поэтому модель для SI должна уметь ловить **собственную** закономерность, часто с **другой дисперсией и асимметрией**.

| Тип | Насколько уместен | Зачем именно для SI |
|-----|-------------------|---------------------|
| LightGBM / XGBoost / HistGBRT / GBR | **Высоко** | Универсальные нелинейные аппроксиматоры в исходной шкале SI. |
| RandomForest / ExtraTrees | **Особенно высоко** | При «капризном» SI и выбросах леса часто **стабильнее** чистых бустингов на малой выборке. |
| Ridge / ElasticNet / BayesianRidge | **Средне** | Если SI в первом приближении выводится из линейных комбинаций дескрипторов, линейки дают устойчивый сигнал; иначе их вес после CV может быть ниже — это нормально. |
| CatBoost (опция) | **Высоко** | Хорошо работает в смеси, когда таргет зашумлён. |

*Итого:* те же **≥9 типов** формально покрывают SI; **акцент анализа** смещён к **лесам + бустингам**, линейные методы остаются в пуле как **контроль диверсификации** ансамбля.

## Связь анализа с кодом

- Для **каждого** таргета обучается **свой** набор экземпляров всех кандидатов (все **≥9** типов × 3 таргета в бандле).
- **Кластерная CV** по train даёт **разные** средние RMSE и **разные веса** для IC50, CC50 и SI — это и есть практическая «настройка наиболее подходящих» вкладов без ручного угадывания.
- Расширенное обоснование семейств — в таблице выше; исключённые из дефолта подходы (SVR, kNN, NN) — в следующем разделе.

## Почему не SVR / kNN / глубокая сеть «по умолчанию»

- **SVR (RBF):** \(O(n^2)\)–\(O(n^3)\) на обучении; на 750 строк ещё терпимо, но подбор C/gamma и CV делают прогон дорогим и нестабильным без отдельного тюнинга.
- **kNN-регрессия:** высокая дисперсия и проклятие размерности при ~200+ признаках после инжиниринга.
- **Нейросеть:** при 750 объектах легко переобучается; разумна как **опциональный** доп. участник с малым весом (см. техдизайн), не как обязательный дефолт.

## Как это используется в коде

- Каждый таргет: обучаются **все** доступные кандидаты из реестра (`build_default_candidates`); по **ClusterKFold** — средняя RMSE; **веса ансамбля** обратно пропорциональны ошибке.
- При установленном **catboost** добавляется ещё один тип (`pip install catboost` или extra в `pyproject`).

- После первого прогона отбросить модели с худшей CV (например, ниже медианы) **отдельно для каждого таргета** — уменьшит время инференса.
