## Часть C. Рекомендации по данным и репозиторию

*(из бэклога и README; дополняют ТЗ, не заменяют код.)*

1. **`data/*.csv`** в `.gitignore` — большие файлы в git **не коммитятся**; после `git clone` снова копировать `train.csv` / `test.csv` локально.
2. **Контракт `train.csv`:** обязательны колонки **IC50, CC50, SI**; иначе ошибка при загрузке.
3. **Согласованность признаков train/test:** все числовые колонки, которые ожидает обученный `Preprocessor`, должны присутствовать в `test.csv` (имена совпадают с train); нечисловые колонки не попадают в модель без доработки кода.
4. **Колонка `index` в test:** желательно как в выдаче соревнования; при отсутствии пайплайн подставит синтетический индекс — риск для платформы.
5. **`sample_submission.csv`** — только формат; **не** заменяет train/test.
6. Если позже понадобится **мини-датасет в git** — заранее выбрать стратегию (исключения в `.gitignore`, подкаталог `data/public/`, конфиг `CHEM_DATA_DIR`) и синхронизировать с README и `.env.example`.

## Часть D. Рекомендации по ML и коду

*(сводка из `Разработка/Ревью/ML_ревью_2026-05-16_архитектура_и_корректность.md` — детали там.)*

### D1. Высокий приоритет (влияет на доверие к CV и весам)

| ID | Тема | Суть |
|----|------|------|
| R1 | CV vs **full** preprocessor | Список признаков на фолде и у `full_pre` может **различаться** → CV RMSE и **веса ансамбля** не строго соответствуют финальному обучению. Варианты: фиксировать список колонок с `full_pre`, пересчитывать только медианы/scaler на фолде; или явно писать в README, что CV — прокси. |
| R2 | **ClusterKFold** | KMeans на **всех** точках до сплита → **утечка** в оценку CV. Улучшение: KMeans только на train-части фолда, назначение val через `predict`. |
| R3 | Производительность train | **Трижды** вызывается `cv.split` по таргетам — вынести список фолдов **один раз** до цикла по таргетам. |

### D2. Средний приоритет

| ID | Тема | Суть |
|----|------|------|
| R4 | Holdout в финальных бустингах | ~10% train не участвует в финальном fit LGB/XGB/Cat из-за early stopping — компромисс; при желании доработать финальный шаг. |
| R5 | Два хранилища preprocessor | `preprocessor.joblib` и бандл — дублирование; лучше один канонический источник или явная пометка в доке. |
| R6 | `NumpySafeLGBMRegressor` | Обход sklearn/LightGBM по именам признаков — ок; см. бэклог п. 2 про оверхед и альтернативы. |
| R7 | Реестр моделей | `candidate_models.py` перегружен — вынести гиперпараметры в конфиги/таблицу для сопровождения. |
| R8 | Нечисловые признаки | Тихий отбор только `numeric` — при появлении важных категориальных признаков — кодирование или расширение пайплайна. |
| R9 | SI и IC50/CC50 | ТЗ допускает **независимый** прогноз SI; при желании добавить ограничения согласованности — отдельное исследование. |

### D3. Низкий приоритет и бэклог LGB

- **Бэклог §2:** оценить оверхед обёртки LightGBM, рассмотреть единый вход `DataFrame` с именами из `Preprocessor.get_feature_names()`, задокументировать или упростить.
- **P3 из ревью:** поведение без `index` в test; неиспользуемый `Log1pWrapper`; версионирование схемы `joblib`-бандла.
