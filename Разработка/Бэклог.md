## 1. Датасет: плейсмент, имена файлов, совместимость с репозиторием

**Цель:** добавить данные так, чтобы `train_pipeline` и `predict_pipeline` **сразу находили файлы и не падали**, а при решении **коммитить CSV в git** не оставались «невидимыми» из‑за `.gitignore` и не ломали CI/коллег.

### Где лежат файлы (по умолчанию)

- Каталог данных задаётся **`CHEM_DATA_DIR`** в `.env` (см. `.env.example`). Если не задано — **`data/`** относительно **текущей рабочей директории** при запуске `python run_pipeline.py` (обычно корень репозитория).
- Обязательные имена (зашиты в `src/chemai/utils/data_loader.py`):
  - **`train.csv`** — обучение: те же числовые признаки, что в соревновании, плюс колонки **`IC50`**, **`CC50`**, **`SI`**.
  - **`test.csv`** — инференс: тот же набор **признаков**, что у train (без таргетов в реальной постановке), плюс колонка **`index`** (если колонки нет — пайплайн подставит синтетический индекс, для платформы лучше явный `index` как в выдаче).
- Опционально: **`sample_submission.csv`** — только для сверки формата; **не заменяет** `train.csv` / `test.csv`.

### Контракт train, чтобы код не «ломался»

- В `train.csv` должны присутствовать все три таргета; иначе `ValueError` при загрузке.
- Колонка **`index`**: для признаков она из `X` убирается — дублировать индекс в двух местах не требуется, но строковые/нечисловые id в других колонках препроцессор **не использует** (берётся только `select_dtypes` с числом) — важные текстовые поля должны быть закодированы заранее или расширить код.
- Порядок колонок в test **не должен** расходиться с train по **именам** числовых признаков: при инференсе `Preprocessor.transform` требует все колонки из `_feature_columns`.

### Если файлы нужно хранить в git

- Сейчас в **`.gitignore`** игнорируются **`data/*.csv`** (защита от случайного коммита больших выборок).
- Чтобы репозиторий содержал, например, **облегчённый учебный набор** и проходил сценарий «клонировал — запустил»:
  - либо добавить **исключения** вида `!data/train_mini.csv` и тогда в коде/`.env` указать другой каталог или имена (потребуется доработка конфига **или** симлинки/копии с именами `train.csv` / `test.csv`);
  - либо вынести мини-датасет в **`data/public/`** и ослабить ignore точечно (`!data/public/*.csv`) — тогда **обязательно** обновить `data_loader` или `CHEM_DATA_DIR` на `data/public`;
  - либо не коммитить большие CSV, а документировать только **Kaggle + шаг копирования** в `data/` (как сейчас в README).
- **Сделать:** выбрать стратегию, синхронизировать `.gitignore`, `.env.example`, README и при необходимости **одну** точку конфигурации (имена файлов или подкаталог), чтобы не было расхождений.

### Критерий готовности

- Локально: `Test-Path .\data\train.csv` / `.\data\test.csv` → `True` (или актуальный `CHEM_DATA_DIR`).
- `python run_pipeline.py --train` и `--predict` завершаются без исключений.
- Если датасет в git — `git clone` на чистой машине + установка зависимостей + те же команды дают тот же результат (или задокументирован минимальный объём данных).
