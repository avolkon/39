## Слайд 2 — Цель задачи и метрика

По условию хакатона (**ТЗ**, раздел «Проблема»): разработка новых лекарственных препаратов — сложный и длительный процесс, включающий синтез соединений и их биологическое тестирование. Современные методы машинного обучения позволяют ускорить этот процесс, предсказывая эффективность химических соединений до проведения лабораторных экспериментов. В этом соревновании вам предстоит выступить в роли ML и Data-инженеров в команде фармацевтической разработки. Химики предоставили данные о свойствах молекул и их биологической активности против вируса гриппа. Ваша задача — построить модели, способные предсказывать эффективность новых соединений.

- **Что предсказываем:** три скалярных таргета — **IC50**, **CC50**, **SI** для малых молекул по набору **≈210** числовых признаков (дескрипторы класса RDKit: Topo/logP/VSA, фрагменты `fr_*` и др.).
- **Формат соревнования:** одна таблица отправки с колонками `index`, IC50, CC50, SI для тестовой выборки.
- **Метрика (как при скоринге):** среднее арифметическое **RMSE** по трём столбцам —  
  \((\mathrm{RMSE}_{IC50}+\mathrm{RMSE}_{CC50}+\mathrm{RMSE}_{SI})/3\) (в коде проекта — логика «среднее по трём RMSE» после согласования длины и отсутствия NaN).

## Слайд 3 — Данные и предметная интерпретация

| Набор | Размер | Содержание |
|-------|--------|------------|
| **train** | **751** строк | 214 колонок: индекс + 3 таргета + 210 признаков |
| **test** | **250** строк | 211 колонок: индекс + те же 210 признаков без меток |

**Доменная особенность:** на train **SI совпадает** с отношением **CC50 / IC50** с точностью до численной погрешности (порядка \(10^{-11}\)), что задаёт возможность использовать **совместность** между столбцами в инженерных экспериментах (с сохранением риска, что на платформе определение SI может расходиться с «частным от двух концентраций»).

## Слайд 4 — Основные факты EDA (структура данных → решения пайплайна)

- **IC50/CC50:** сильные **правые хвосты** распределений → в модели включено **`log1p`** при обучении по этим двум таргетам и **`expm1`** на восстановленный масштаб прогноза.
- **Сигнал «не узкий по одному признаку»:** топ-корреляции с таргетами лишь **умеренные** (порядка 0.2–0.3\) → оправданны **мультипризнаковые** модели высокой ёмкости с регуляризацией: бустинг, леса, линейные модели после масштабирования.
- **Шум признаков:** константы, почти константы, редкие пропуски → **Preprocessor** отсекает слабоинформативные столбцы и заполняет пропуски.
- **~16 % объектов-дубликатов по вектору признаков** → вместо наивного KFold используется **ClusterKFold** по структурно осмысленному подмножеству признаков, чтобы смягчить «слишком оптимистичную» валидацию.

## Слайд 5 — Смещение train → test и риски обобщения

- Выявлен **covariate shift** между train и test по ряду признаков (в т.ч. отдельные `fr_*`, размерность/форма ядер колец и др.).
- **Следствие:** оценки качества, завязанные только на train-дистрибуцию без учёта сдвига, могут **переоценивать перенос** на платформе.
- **Практическая реакция:** опора на устойчивые семейства (дерева/бустинг), аккуратный препроцессинг без утечки с тестом, строгое переобучение **Preprocessor только внутри train-фолда** CV.

## Слайд 6 — Базовое решение в репозитории («ядро воспроизводимости»)

- Обучение: **`train.py`** (запуск: **`python run_pipeline.py --train`**).
- **CV:** **`ClusterKFold`**; препроцессор переобучается **на каждом фолде** только на его train-индексах (**честная валидация**).
- **Три таргета** моделируются **раздельно** — для каждого свой состав кандидатов и свой вектор **весов ансамбля** из CV (**обратные среднему RMSE на фолдах**, нормировка до распределения весов).
- **Финальный прогон:** дообучение на полном train с сохранением бандла:  
  **`preprocessor.joblib`**, **`pipeline_bundle.joblib`**, **`metrics.json`**.

## Слайд 7 — Ансамбль базовых моделей

- Из коробки: **минимум 9 семейств** регрессоров: LightGBM, XGBoost, HistGradientBoosting, случайный лес, экстремальные деревья, sklearn GradientBoosting, RidgeCV+, Elastic-Net+, Bayesian Ridge+ (**+** здесь связка со **`StandardScaler`** в коде пайплайна кандидатов).

- Ансамбль первого уровня: **взвешенное среднее** прогнозов по имени модели (**без второго stacking-слоя** в официальной ветке `train.py`).
- В типичных прогонах **перекос CV** может «обнулить» веса нестабильных линейных кандидатов — вклад финала чаще **деревьями и бустингом**.

## Слайд 9 — Серия офлайновых экспериментов и публичный лидерборд (зафиксировано командой)

- Параллельно рассмотрены отправки класса **`submission*_a4`**: связка **OOF stacking** (Ridge на out-of-fold предсказаниях базового пула моделей при **cluster-CV** как в коде), вариант с подбором **смеси SI**, вариант с **GroupKFold** по группам дубликатов + Optuna над LightGBM.
- **На публичной части лидерборда** (ChemAI):  
  • **~349.31** — лучшие варианты **stacking/cluster** (**`submission2_a4`** / **`submission3_a4`**, смесь SI дала те же баллы после отбора веса).  
  • **~373.04** — вариант с **group split** + stacking (**`submission4_a4`**, **`submission5_a4`**).  
**Интерпретация:** более «строгая» офлайновая группировка **не перевелась в выигрыш на тесте** — возможный разрыв OOF versus скрытый сплит.
- **Операционно сейчас:** в узком поддерживаемом дереве проекта сохранён **единый вход** через **`train`/`predict`**; повтор генерации «рекордных» отправок возможен восстановлением исторического tooling из веток git при необходимости.

## Слайд 10 — Выводы

1. **Данные:** малая выборка train (**751**) при многодескриптурном описании (**~210** числовых колонок) + сильная асимметрия активностей, дубликаты, сдвиг train→test — классический **табличный QSPR / SAR** с задачами **обобщения**, а не «одним сильнейшим фактором».
2. **Базовая архитектура ChemAi** воспроизводима через **`train`/`predict`**: ClusterKFold, **честный** фолдовый preprocessor, семейство сильных табличных регрессоров + **пер-таргетные** ансамблевые веса из CV.
3. **Лучший зафиксированный платформенный результат** описанной серии — отправки порядка **349.31** за счёт **OOF stacking второго слоя без правок базового `train`** (поддерживавший скрипт в текущей «узкой» сборке удалён как не core).
4. **Риск переоптимизации под офлайновую группировку**: GroupKFold-вариант **улучшал OOF** по среднему RMSE цепочкой из трёх таргетов, но **ухудшал** leaderboard — нужна осторожность при трактовке «честной» CV только по одной статистике.
5. **Направления роста (резерв):** общая мета-цель сразу на среднее RMSE по трём столбцам при подборе весов, осознанное использование **связи SI с IC50/CC50** после платформенной верификации, полноценный **Optuna/stacking**, контролируемый групповый split только при подтверждении трансфера на платформе.
